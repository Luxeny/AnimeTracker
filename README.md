# AnimeTracker

**AnimeTracker** — это современное Android-приложение для поиска аниме, просмотра подробной информации и управления личным списком (Watchlist). Приложение разработано с использованием актуальных технологий и подходов к архитектуре Android.

## Основные возможности

- **Поиск аниме**: Быстрый поиск по базе Shikimori API с дебаунсом.
- **Рекомендации**: Бесконечный список случайных аниме на главном экране (пагинация).
- **Детальная информация**: Описание, рейтинг, жанры и количество эпизодов.
- **Watchlist (Мой список)**: Возможность добавлять аниме в список, отмечать количество просмотренных серий, ставить оценку и писать заметки.
- **Аналитика**: Отслеживание просмотров экранов через сервис аналитики.

## Технологический стек

- **Язык**: Kotlin
- **UI**: Jetpack Compose (Material 3)
- **Архитектура**: Clean Architecture + MVVM + MVI-like State Management.
- **Многомодульность**: Проект разделен на 17 модулей (фичи и слои).
- **Dependency Injection**: Koin
- **Сеть**: Retrofit + OkHttp + Moshi
- **База данных**: Room (для хранения Watchlist)
- **Асинхронность**: Kotlin Coroutines + Flow
- **Навигация**: Custom Navigation (Type-safe) в отдельном модуле `:core:navigation`.
- **Архитектурные проверки**: Konsist (проверка правил модульности и зависимостей).
- **Управление зависимостями**: Gradle Version Catalog (`libs.versions.toml`).

## Архитектура проекта

Проект реализован в соответствии с подходом **Combined Modularization**:
- `:app` — основной модуль, точка входа и DI-контейнер.
- `:core` — общие модули (сеть, база данных, модели, навигация, аналитика).
- `:feature` — модули функциональных возможностей. Каждая фича разделена на слои:
    - `:domain` — бизнес-логика, модели и интерфейсы репозиториев (без зависимостей от Android).
    - `:data` — реализация репозиториев, работа с API и локальной БД.
    - `:ui` — интерфейс пользователя на Compose.

## Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/Luxeny/AnimeTracker.git
   ```
2. Откройте проект в Android Studio (Ladybug или новее).
3. Создайте файл `.env` в корне проекта на основе `.env.example` (если требуется для ключей API).
4. Запустите проект на эмуляторе или физическом устройстве.

## Тестирование

- **Unit-тесты**: Тестирование ViewModel и бизнес-логики.
- **Архитектурные тесты**: В модуле `:app` находятся тесты Konsist, проверяющие соблюдение архитектурных правил (например, что `domain` не зависит от Android-библиотек).
